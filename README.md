# GoPETshop — REST API магазина товаров для животных

Учебный проект на Go и PostgreSQL. Приложение развивалось в четырёх версиях: от управления пользователями и товарами до оформления заказов в транзакции и аналитических запросов.

## Развитие проекта

### V1 — Пользователи и товары

В первой версии реализован базовый REST API магазина:

- создание пользователя, получение пользователя по email и списка пользователей;
- создание, просмотр, изменение и удаление товаров;
- получение товара по ID;
- валидация входных данных и обработка HTTP-ошибок;
- хранение данных в PostgreSQL через `pgx`;
- логирование через `slog` и unit-тесты HTTP-обработчиков с mock-хранилищами.

**Зачем:** создать основу приложения, освоить работу с HTTP, PostgreSQL и разделение кода на обработчики, модели и слой хранения.

### V2 — Заказы и позиции заказов

Добавлена работа с заказами:

- создание заказа и получение заказа по ID;
- получение заказов пользователя: `GET /users/{email}/orders`;
- добавление товаров в заказ и просмотр его позиций;
- связи между `users`, `orders`, `order_items` и `products` через внешние ключи;
- пересчёт `total_price` по количеству товаров и их стоимости;
- обработка ошибок и тесты новых обработчиков.

**Зачем:** научиться работать со связанными таблицами, SQL `JOIN` и расчётом стоимости заказа.

### V3 — Checkout и транзакции

Добавлено оформление заказа через `POST /checkout`:

- поиск пользователя по email;
- проверка существования товара и достаточности остатка на складе;
- создание заказа и его позиций;
- уменьшение `stock` и вычисление `total_price`;
- сохранение записи в таблице `transactions`;
- выполнение операций в одной PostgreSQL-транзакции: `COMMIT` при успехе и `ROLLBACK` при ошибке;
- отдельный обработчик checkout и unit-тесты.

**Зачем:** обеспечить атомарность оформления заказа — нельзя списать товар со склада, если остальные операции завершились с ошибкой.

### V4 — Аналитика

Добавлены SQL-запросы с использованием `JOIN`, `GROUP BY` и `SUM`:

- история заказов пользователя: `GET /users/{email}/history`;
- рейтинг популярных товаров: `GET /products/popular`;
- подсчёт количества проданных единиц через `SUM(order_items.quantity)`;
- учёт завершённых транзакций при расчёте популярных товаров;
- unit-тесты аналитических HTTP-обработчиков.

**Зачем:** научиться объединять данные из нескольких таблиц, строить агрегирующие запросы и предоставлять результаты через API.

История заказов содержит ID заказа, товар, количество, общую стоимость заказа, статус транзакции и дату создания. Популярные товары сортируются по количеству проданных единиц.

## API

### Пользователи

```text
POST /users
GET  /users
GET  /users/{email}
GET  /users/{email}/orders
GET  /users/{email}/history
```

### Товары

```text
POST   /products
GET    /products
GET    /products/{id}
PUT    /products/{id}
DELETE /products/{id}
GET    /products/popular
```

### Заказы

```text
POST /orders
GET  /orders/{id}
POST /orders/{id}/items
GET  /orders/{id}/items
```

### Checkout

```text
POST /checkout
```

Оформляет заказ с проверкой остатков и записью результата в БД в рамках одной транзакции.

### Проверка состояния приложения

```text
GET /health
```

## Технологии

- Go (`net/http`, `chi`, `slog`);
- PostgreSQL (`pgx/pgxpool`, SQL, транзакции и миграции);
- Docker и Docker Compose;
- unit-тесты с `testing`, `httptest` и собственными mock-реализациями;
- `golangci-lint`.

## Переменные окружения

Создайте файл `.env` на основе `.env.example` и задайте настройки подключения к PostgreSQL. Не добавляйте `.env` с настоящими паролями в Git.

## Запуск через Docker

Запуск приложения и PostgreSQL с применением миграций:

```bash
docker compose up --build
```

Остановка контейнеров:

```bash
docker compose down
```

Остановка с удалением тома и данных PostgreSQL:

```bash
docker compose down -v
```

## Тесты

Запуск всех тестов:

```bash
go test ./...
```

Подробный вывод:

```bash
go test -v ./...
```

## Линтер

```bash
golangci-lint run ./...
```

## Форматирование

go fmt ./...
